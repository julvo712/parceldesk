# ParcelDesk: 15-minute version

Use [the full script](presenter-25min.md) for preparation and exact commands. Keep one coding tool on screen.

1. **0–3 minutes — useful outcome.** Replace Maya’s damaged headphones, confirm explicitly, refresh. Open its trace and generation.
2. **3–5 minutes — development economics.** Show the genuine coding session, tokens/cache, cost coverage and explicit task link. State that costs are API-equivalent estimates and productivity is measured delivery activity.
3. **5–8 minutes — trust boundary.** Run supplier injection, inspect actual model behavior, then run the clearly disclosed native guard probe. Distinguish prompt resistance, native denial and business authorization.
4. **8–12 minutes — improve and evaluate.** Start the bounded prompt edit or show its actual diff. Compare saved real full-suite experiments while the new smoke run executes. Show a rejected candidate and the accepted version, including benign-case regressions.
5. **12–15 minutes — close the loop.** Activate only accepted evidence, start a new conversation, verify the persisted outcome. Summarize coding consumption → evaluated change → customer result.

For an SRE-heavy audience, replace the live edit with the CPU-span or database-lock chapter. For a security-heavy audience, spend that time on guard failure, false refusals and evaluation coverage. Preserve the customer outcome at the beginning and end.
